  • Technical Localization Audit: Standardizing tooltip syntax, removing linguistic ambiguities, and unifying keyword conventions.
  • UI/UX Evaluation: Enhancing action clarity, readability, and interface navigation during tactical combat.
  • Systemic Balance Analysis: Addressing progression walls, combat scaling (Crit/DoTs), and Hardcore mode dynamics.

Executive Summary ↑

Clear and precise UI descriptions prevent unnecessary cognitive friction during tactical decision-making. While Tenebris: Terra Incognita features a remarkably deep and engaging combat engine, systemic inconsistencies in localization, UI syntax, and endgame progression currently obscure its full potential.

This report presents a structured analysis and actionable framework focused on three core pillars:

  • Technical Localization & UI Syntax: Standardizing tooltip terminology (e.g., unifying Provocation vs. Taunt, establishing Killing Blow), stripping redundant adverbs/operators, and removing syntactic ambiguity to streamline combat readability.
  • Systemic Gameplay & Meta Balance: Addressing midgame progression walls via HQ mission capping, smoothing Hardcore mode reinforcement mechanics, capping uncapped Critical Damage, and introducing targeted DoT detonation mechanics for classes lacking immediate direct burst.
  • Equipment & Interface Quality-of-Life: Curating random loot generation to eliminate "dead stats", aligning item headers with class lore, and proposing essential UX additions such as UI scaling, keyboard shortcuts, and replayable endgame structures.

1. General Syntax & UI Formatting Rules ↑

1.1 Redundant Adverbs & Typos ("instantly" / "immediately")

Many passive and buff descriptions currently rely on filler adverbs like "instantly" or "immediately" (along with minor localization typos such as "immidiately"). In a turn-based tactical system, mechanical status updates and stat modifications are instant by default.

💡 TIP
Rule: Strip out all instances of "instantly", "immediately", and their typos across all tooltips.

1.2 Mathematical & Punctuation Redundancy (+, %, Increases)

Tooltips frequently mix plain language verbs with explicit mathematical operators:

  • Redundant Symbols: Combining verb indicators with operators (e.g., "Increases duration by +1 raid").
  • Double Percent Symbols: Appending % to both the stat name and value (e.g., "Increases Crit. Damage % by +10%").
📌 IMPORTANT
Standardization Rules:
1. When using verbs like Increases or Reduces, omit the + and - operators.
2. Primary Standard (Option A - Recommended): Stat Name + % Value (e.g., "Increases Bonus Exp by 25%.").
3. Secondary Standard (Option B - Compact): Stat % Keyword + Integer Value (e.g., "Increases Bonus Exp% by 25.").

Conversion Examples:

  • Battle Tested (Buff Tooltip):
    • Current: "Increases Crit. Damage % by +10%."
    • Proposed (Option A): Increases Crit Damage by 10%.
    • Proposed (Option B): Increases Crit Damage% by 10.
  • Portable Injector (Item Tooltip):
    • Current: "Increases the duration of stimulants from the Medbay by +1 raid."
    • Proposed: Increases Medbay stimulant duration by 1 raid.

1.3 Currency Terminology Standardization ("Credits" vs. "Honor")

Several perk tooltips (e.g., Archaeologist referencing "finding more credits") and narrative dialogues occasionally refer to in-game currency as "credits". However, the actual transactional currency utilized throughout the game's economy is named Honor, featuring an icon and framework completely detached from credit-based terminology.

⚠ TERMINOLOGY RULE
Audit and standardize all instances of "credits" across tooltips, item descriptions, and localization strings, replacing them with Honor to prevent confusion with the actual in-game economy.

1.4 Targeting & Area of Effect (AoE) Terminology Standardization

We strongly recommend a sweeping cleanup and normalization of targeting and area-of-effect phrasing across all skill descriptions. Spatial definitions frequently suffer from disarray, occasionally showing direct contradictions between body text and formal area tags (e.g., skills describing row-wide impacts while displaying column tags). Unifying these spatial definitions and clarifying single-target freedoms (such as Any Target vs. Frontline Target) will eliminate grid-based confusion.

1.5 Definite Article Redundancy in English Localization

Rationale: The English localization frequently appends unnecessary definite articles before status effect names, mechanical keywords, and passive traits (e.g., writing "the Nano Plague effect", "the Shock", or "the Battle Tested"). In tactical UI writing, status keywords function as proper nouns or established status states and read much cleaner without preceding articles like "the".

💡 GRAMMAR & LOCALIZATION RULE
Strip out unnecessary definite articles ("the") preceding status effects, status categories, and systemic keywords across English localization strings.

Examples:

  • Current: "When attacking a target affected by the Nano Plague effect..."
  • Proposed: "When attacking a target affected by Nano Plague..."
  • Current: "Applies the Shock effect to the target."
  • Proposed: "Applies Shock to the target."

2. Combat Tooltips, Keywords & UI Case Studies ↑

Case Study #1: On-Kill Triggers & System Keyword Integration

Currently, the game uses disparate phrasing for defeating targets (e.g., "finishing blow", "finishing off a target", or "for each kill"). Standardizing these under a unified keyword removes mechanical ambiguity regarding whether DoT effects or indirect status kills qualify.

ℹ SYSTEM KEYWORD IMPLEMENTATION
Recommendation: Formalize a dedicated system keyword—Killing Blow—leveraging in-game hover tooltips.
Hover Tooltip Definition: Triggered exclusively when a hero defeats an enemy using direct damage (excludes damage-over-time effects like Poison, Bleed, or Acid).

Conversions:

  • Special Training 2:
    • Current: "For each finishing blow applies the Battle tested x5 effect on self. The effect is cumulative."
    • Proposed: Killing Blow: Grants Battle Tested (x5). (Stacks)
  • Special Training III:
    • Current: "When finishing off a target with direct damage: Gains an action point."
    • Proposed: Killing Blow: Action does not end.
  • Battle Wolf:
    • Current: "For each kill, grants the hero Unity x5."
    • Proposed: Killing Blow: Grants Unity (x5).

Case Study #2: Standardized Turn-Phase Prefixes

Rationale: Establishing strict structural prefixes ensures players immediately recognize phase-based passive activations across skill trees.

📌 STANDARDIZATION RULE
Standardize all phase-based conditional triggers to the exact prefixes "At start of turn:" and "At end of turn:" followed by a colon.

Conversions:

  • Start-of-Turn Trigger:
    • Current: "When turn starts, restores 10 Health to the hero."
    • Proposed: At start of turn: Restores 10 Health.
  • End-of-Turn Trigger:
    • Current: "On turn end as a 15% chance to apply Fatigue x1 effect."
    • Proposed: At end of turn: 15% chance to apply Fatigue (x1).

Case Study #3: On-Miss Mechanics & Reset Conditions

Rationale: Removing redundant adverbs like "instantly" and consolidating trigger/reset conditions makes stacking passives easier to parse during combat.

  • Current: "Each miss instantly increases the hero's Accuracy by 15% until a successful hit. Stacks up to 5 times."
  • Proposed: Missing a hit increases Accuracy by 15%. Stacks up to 5 times, resets on hit.

Case Study #4: Disjunctive Triggers & Consolidated Syntax

Rationale: Combining multi-choice triggers under a single structural clause saves tooltip space and flows better visually.

  • Current: At the end of the turn as a 15% chance to apply Fatigue x1 effect. OR At the end of the turn as a 15% chance to apply Bionanobots x1 effect.
  • Proposed: At end of turn: 15% chance to apply Fatigue (x1) or Bionanobots (x1).

Case Study #5: Inconsistent Initiative Reduction Terminology

Across character skill trees, turn-manipulation mechanics exhibit fragmented phrasing (e.g., "Increases Initiative damage" vs. "Deals Initiative damage at X%"). Since these function identically to standard initiative reductions, unifying them under "Reduces target Initiative by X% per hit" clarifies multi-strike skill behavior.

Conversion Examples:

  • Bloody Job:
    Current: "Applies Bleeding x1 effect. Increases Initiative damage by 5%."
    Proposed: Applies Bleeding (x1). Reduces target Initiative by 5% per hit.
  • Total Disinfection:
    Current: "When attacking a target affected by the Nano Plague effect: Deals Initiative damage at 50%."
    Proposed: When attacking a target affected by Nano Plague: Reduces target Initiative by 50% per hit.

Case Study #6: Conditional Punctuation & Trigger Headers

Rationale: Replacing informal hyphens with colons establishes a clean visual hierarchy between conditions and effects.

  • Current (Taking the Initiative): "When Ambushed - increases Initiative by 125%."
  • Proposed: When Ambushed: Increases Initiative by 125%.

Case Study #7: Structural Line-Wrapping & Split Quantifiers

Rationale: Multi-line condition texts occasionally wrap awkwardly across UI containers. Formatting multi-tier scaling into nested lists prevents broken layout lines.

Conversion Example:

  • Special Training III (Lautus Specialization):
    Current (Broken Line-Wrap):
    "At the start of the turn, restores health to the hero by
    For each Toxin on enemies +4.
    For each Nano Plague on enemies,
    +30."

    Proposed Format: At start of turn: Restores Health based on active enemy debuffs:
    • Toxin: +4 Health per stack.
    • Nano Plague: +30 Health per stack.

Case Study #8: Redundant Resistance Listings & Hyperlink Scope

Rationale: Multi-line resistance buffs repeat "Increases [Stat] Resistance by +100%" across separate lines. Grouping these resistances into a single consolidated clause (matching the character sheet order: Paralysis, Fear, Knockdown, Stun) streamlines tooltip card size.

Conversion Examples:

  • Pressure Compensator:
    Current: Increases Fear Resistance by +100%... (4 separate lines)
    Proposed: Increases Paralysis, Fear, Knockdown, and Stun Resistance by 100%.

Case Study #9: Multi-Debuff Scaling & UI Container Layouts

Rationale: Formatting multi-debuff efficiency scaling into structured sub-lists avoids text clipping inside tooltip cards.

Conversion Example:

  • Test Subject (Lautus Specialization):
    Current (Inline Overflow): "Reduces initiative: For each Poison on a target, 1%..."
    Proposed Format: Reduces target Initiative based on active status effects:
    • Poison: -1% Initiative per stack.
    • Toxin: -10% Initiative per stack.
    • Nano Plague: -75% Initiative per stack and applies Fear (x1).

Case Study #10: Status Effect Synonym Conflicts (Provocation vs. Taunt)

Rationale: The aggro-redirect effect is established as Provocation throughout most of the game, matching both the active debuff icon and hover hyperlink. However, specific skills (such as High Explosive Drive and Heavy Shotgun) refer to it as "Taunt". Aligning these isolated instances under Provocation ensures consistency.

⚠ TERMINOLOGY UNIFICATION RULE
Standardize all occurrences, skill descriptions, and tooltips strictly to Provocation across the entire game.

Conversion Examples:

  • High Explosive Drive:
    Current: "Grants a 20% chance to apply the Stun x1 effect. If the target has the Taunt effect, applies the Stun x1 effect."
    Proposed: 20% chance to apply Stun (x1). If the target has Provocation, applies Stun (x1).
  • Heavy Shotgun:
    Current: "If the target has the Taunt effect: Increases Crit. Chance % by 100%."
    Proposed: If the target has Provocation: Increases Crit Chance by 100%.

Case Study #11: Action Economy Phrasing Inconsistencies

Rationale: Unifying extra-action triggers under standard phrasing improves tactical clarity across different class trees.

📌 ACTION ECONOMY RULE
Unify extra-action grants under a consistent standard (e.g., "Grants an extra action (Once per round)." or "Action does not end.").

Case Study #12: Semantic Overuse of the Verb "Burn"

Rationale: Using "Burn" for initiative draining or stack removal causes semantic confusion with the actual Burning DoT status effect. Reserving "Burn" exclusively for damage-over-time interactions and using Drain or Consume for resource manipulation clarifies skill behavior.

3. Gameplay Systems & UI/UX Enhancements ↑

3.1 Gameplay & Difficulty Balancing

  • Experience Curve Breakdown & The Midgame Grind Wall:

    The campaign starts with a smooth, highly rewarding rhythm, but hits a jarring midgame wall where natural progression grinds to a painful halt. To keep pace, the game heavily pushes players toward passive leveling via HQ missions. However, because HQ mission brackets scale dynamically based on the active level spread of your entire roster (spanning wildly from a lowly level 4 recruit up to a level 22 veteran all at once), players are funneled into a bizarre loop. You find yourself repeatedly running trivial, mind-numbing low-tier assignments—such as grinding the baseline level 1 mission over and over—just to passively power-level backup characters.

    💡 PROGRESSION & HQ RESTRUCTURING
    HQ missions should be intelligently capped relative to the highest-tier unlocked campaign mission (e.g., if your peak campaign milestone is level 4, HQ offers should not exceed level 4). While this structural cap alone won't completely solve the occasional wild spikes in recommended campaign difficulty, it stops total progression breakage. Furthermore, playtesting with a modest +20% global Experience boost proved to be an absolute game-changer: it smooths out the rough edges of the leveling curve naturally, keeping you right on track without ever feeling overpowered or trivializing the core tactical challenge.
  • Hardcore Permanent Death & Reinforcement Pressure:

    Playing in Hardcore mode is a tense, high-stakes experience, but it suffers from a punishing design collision. When a treasured squad member falls in combat, they are gone forever—there is no safety net, no recovery buffer, and no "Death's Door" mechanic (à la Darkest Dungeon) to offer a dramatic last-second reprieve. Compounding this permanent loss, the reinforcement system in Hardcore can feel brutally unfair: the exact moment you finally manage to put down a dangerous enemy, a fresh high-stat reinforcement instantly pops into existence and is allowed to act immediately on that very same turn, often wiping out a wounded operator before you even have a chance to react.

    ⚠ HARDCORE COMBAT TWEAK
    Introducing a 1-turn Summoning Sickness or automatically placing newly spawned reinforcements at the absolute tail-end of the Initiative Order would restore tactical fairness, giving players a fighting chance to reposition and adapt.
  • Armor Bypass vs. Tactical Armor Shredding:

    Certain skills that completely ignore enemy Armor warp the combat meta entirely. In the early game, they let players completely bypass core tactical layers; by late game, they allow you to completely bypass heavyweight boss stats, making armor-mitigation systems, positioning, and synergy-heavy shredding setups feel obsolete.

    💡 BALANCING SUGGESTION
    Relegate total armor bypass to just one or two iconic signature tools (such as the Pellentes's Bursting Bullet) and instead lean heavily into expanding Armor Shredding / Armor Damage—supercharging the tactical armor-chipping mechanics that are already partially seeded in the game's existing toolset.
  • Uncapped Critical Damage Scaling & DoT Devaluation:

    Critical Damage currently suffers from uncapped, infinite scaling, allowing optimized builds to skyrocket past 1000% Critical Damage. This creates an unbridgeable chasm in the DPS meta:

    • Build Monoculture: Direct crit-stacking builds completely overshadow all alternative playstyles, forcing players into a narrow meta where flat Damage, Crit Chance, and Crit Multipliers are mandatory.
    • Damage-Over-Time (DoT) Devaluation: Status-based playstyles (Bleed, Poison, Acid, Burning) are left completely obsolete. Because DoTs tick exclusively at the end of an enemy's turn and lack critical scaling, even conditional incentives like "+Bonus Damage vs. Bleeding" cannot compete with the blistering burst of hyper-stacked Crit multipliers. Furthermore, the game currently lacks reliable DoT detonation or burst conversion mechanics for status-heavy archetypes that struggle with immediate direct damage.
    💡 BUILD DIVERSITY RECOMMENDATIONS
    Proposed Fixes:
    • Critical Damage Cap: Implement a structural ceiling/cap on Critical Damage % to rein in the runaway direct-damage meta.
    • Targeted DoT Detonation Mechanics: Introduce dedicated DoT detonation or stack-threshold burst mechanics (e.g., instant damage triggers or localized AoE splash upon reaching stack caps, without consuming stacks) specifically for DoT-reliant classes like Lautus, Phoenix, and Berserker to improve their immediate damage output.
  • Class-Locked Field Actions & Roster Progression Walls:

    Exploration and map interaction feature unique "field actions"—such as forcing open blocked pathways or reviving fallen soldiers. However, these interactive opportunities are locked almost exclusively inside specific, non-repeatable main story missions. If you run a mission without a specific class in your active squad, you permanently miss the chance to trigger those field interactions and unlock the tied passive traits for those neglected characters. Adding repeatable field nodes or flexible squad requirements would prevent these permanent build-locking frustrations.

  • Endgame Content Deserts & Procedural Potential:

    Once players push through the campaign, the endgame opens up into a vast vacuum—aside from the final dungeon (which doesn't offer a punishing enough tactical payoff), there is practically nothing left to sink your teeth into. It's a real missed opportunity because Tenebris boasts gorgeous, highly atmospheric background art and a deeply satisfying combat engine. Introducing an extended, replayable endgame mode—such as an endless 100-floor procedural megadungeon that dynamically stitches together the game's underutilized environmental backgrounds—would give fully optimized squads a brilliant reason to keep playing for hundreds of hours.

3.2 Equipment & Item System Rules

  • Archetype Equipment Naming Alignment:

    Nothing breaks immersion quite like interface dissonance. When a Mech class talent tree explicitly teaches you to upgrade "the outer hull," but the item card header in your inventory stubbornly reads "HEAVY ARMOR," it forces unnecessary mental gymnastics. Aligning Mech item headers directly to OUTER HULL creates seamless continuity between skill text and gear management.

  • Dead Stats & Class-Specific Loot Curation:

    Random loot tables are currently plagued by frustrating dead-stat combinations that violate class logic. Mech heavy armor frequently rolls Bio-nanobots (despite Mechs having zero bio-tech integration), Engineer support drones roll useless Bleed modifiers, and general Implants generate wildly conflicting lines (like mixing Panacea, Bleed, and Acid together). Restricting random generation strictly to class-legal attribute pools will make gear hunting feel rewarding rather than punishing.

  • Health Stat Distribution Flaws:

    Right now, the coveted Health attribute rolls almost exclusively on Heavy Armor—the exact gear type worn by heavy-duty classes who already boast massive native health pools. Conversely, Light and Medium Armor classes, who desperately need survival scaling to stay viable on the frontlines, are completely starved of Health rolls on their gear tables.

  • Stat Cap Visibility & Inventory Sorting:

    The game keeps its maximum stat caps entirely hidden from the player (with Critical Chance at 10% being the sole exception discovered through heavy trial and error). Implementing dynamic color coding—such as turning a stat string into a distinct highlight color the moment it hits its maximum ceiling—would be an immense UI quality-of-life win. Furthermore, standardizing secondary stat lines on equipment cards to mirror the order of the character's Details / Resistance panel will make gear comparison snappy and intuitive.

3.3 Interface & System Enhancements (UI/UX)

  • Pass Turn / End Turn Shortcut: Assigning a default remappable keybind (e.g., F) for Pass Turn / End Turn during combat would eliminate repetitive mouse travel across lengthy turn cycles.
  • In-Game Codex & Glossary Tab: Adding a searchable Codex/Glossary to the pause menu allows players to quickly look up status definitions, damage types, and combat keywords during play.
  • Quickbar Keybind Display Sync: Ensuring quickbar UI labels dynamically update when action slot hotkeys are remapped in the settings menu resolves static keybind label bugs.
  • Global UI Scaling & Accessibility: Adding a global UI Scale Slider in the options menu will greatly improve readability for perk icons, Data Center upgrade cards, and small text across high-resolution displays.
  • Status Indicator Color-Coding: Standardizing status indicators—using Green/Blue for positive Buffs and Red/Orange for Debuffs—will make target status evaluation at a glance seamless.

💡 REFERENCE MOD
Reference Mod: QoL - Tenebris + Framework by brakbama (Nexus Mods)

We recommend taking a look at the QoL - Tenebris project by community member brakbama. While community mods are naturally work-in-progress solutions, this project introduces several thoughtful interface ideas that align closely with the UI/UX enhancements discussed in this report:

  1. Dynamic Hotbar Tooltip Aggregation: Hotbar tooltips aggregate active passive/gear multipliers, making total output calculation straightforward.
  2. Passive Amplifier Mini-Tooltips: Side-by-side mini-tooltips highlight passives currently modifying an active skill.
  3. Class Restriction Ring Indicators: Skills locked by subsequent class paths display a visual indicator, helping players plan build paths.
  4. Inventory Rendering Optimization: Off-screen UI cell culling provides smooth scrolling through large equipment inventories.
